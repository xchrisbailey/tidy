# #15 — why I01 and S01 abstained

2026-11-03. **Cause confirmed: OCR corrupted and fused the identifier/date, then
the coordinator deliberately refused that ambiguous evidence before naming.**
The expected names are sufficient given the original source text, but that is not
the text supplied by native OCR. No production fix or safety relaxation was made.

## Reproduction

A temporary opt-in packaged probe recreated only I01/S01 from the unchanged corpus
and their existing native generators, then called the public coordinator with the
same content-naming request and approved actual local model. It asserted the
desired one rename per fixture to make the missed opportunity reproducible:

```sh
env NSUnbufferedIO=YES \
  TIDY_ABSTENTION_OUTPUT="$PWD/.build/native-matrix/abstention-diagnosis" \
  bash scripts/model-smoke.sh --diagnose-abstentions
```

Both cases reproduced zero changes, one `insufficient` abstention, unchanged source
bytes and a nonzero diagnostic result. A second run captured only these synthetic
completion boundaries: each model response was a valid content-naming intent; no
content/title completion was requested. A third run temporarily instrumented the
specific fused-OCR guard and confirmed it fired for each case.

This command was a **temporary diagnostic**, not a new permanent smoke option.
Its source is retained under `.build/native-matrix/AbstentionDiagnostic.swift`;
the temporary flag, raw-response capture and production trace were removed after
diagnosis. The clean packaged diagnostic was rebuilt. Existing unrelated local
lifecycle/resource work was preserved.

## Actual extracted text

The retained generated PNG and raster-only PDF were visually inspected by the
agent. Both show the intended headings with distinct identifier/date tokens;
the PDF contains no native text layer. Running the packaged inspection helper
on the exact generated bytes returned:

| Case | Visible/source heading | Actual OCR heading |
| --- | --- | --- |
| I01 | `Acme Invoice AI901 2026-10-01` | `Acme Invoice A19012026-10-01` |
| S01 | `Pine Invoice PI301 2026-03-14` | `Pine Invoice P13012026-03-14` |

OCR confused capital **I** with digit **1** and omitted the separator before the
date. S01 also misread body prose (`office entrance` as `offits entrantt`), though
that was not the guard that stopped naming. The helper returned `code: ok`, with
`imageOCR/wholeImage` for I01 and `pdfTextAndOCR/wholeDocument` for S01. Thus neither
case was rejected because the image was unsupported, malformed, empty or beyond
the input/coverage limits.

## Exact control flow

```text
original PNG / raster PDF
  native Vision OCR accepts recognized text
    identifier + date arrive as one ambiguous token
      coordinator fused-identifier/date guard matches
        insufficient evidence; no naming completion; no rename
```

[`ContentNaming.swift`](../../Sources/TidyCore/ContentNaming.swift) checks OCR
evidence for an alphanumeric token fused to a date-shaped suffix. It explicitly
refuses to split/repair that value or represent it as a reliable identifier/date.
The captured strings match that check, and temporary branch instrumentation
confirmed the actual coordinator path—not merely a matching regex in isolation.

The naming model therefore did **not** decide that an invoice heading was too
generic, omit a known good title, or exhaust its replacement attempt. It never
received content evidence for these two files. The observed safe abstention is
intentional; the usability limitation originates in OCR extraction/tokenization.

The current helper uses Vision revision 3, fast recognition, CPU compute and no
language correction. Its source records an earlier accurate-recognition compiler/
cache initialization problem under containment. That historical issue explains
the current configuration; this diagnosis did **not** test whether another mode,
scale or language-correction setting would fix these cases safely.

## Implication and next implementation boundary

Do not remove the fused-token guard, automatically split date-shaped suffixes, or
substitute known corpus IDs: even adding a separator would leave `A1901`/`P1301`
instead of `AI901`/`PI301`. The source text is known to the synthetic fixture
generator, not independently known to production naming.

A real improvement belongs in OCR extraction: preserve word/token boundaries and
obtain sufficient recognition evidence for the actual identifier while retaining
containment, resource limits and refusal of ambiguity. Candidate changes need
their own tests against original images, adversarial fused identifiers, ordinary
positive cases and the unchanged full corpus. No claim that a specific untested
OCR setting solves this is made here.

The existing integration regression
`fusedOCRIdentifierAndDateAbstainsInsteadOfGuessingBoundaries` passed after trace
removal. It verifies abstention before naming, unchanged bytes and empty history.
Lint and whitespace checks passed; no new dependencies or production changes were
needed for this diagnosis.
